# Crypto Tracker API

REST API для отслеживания курсов криптовалют. Сервис ведёт список отслеживаемых монет, получает актуальные курсы из [CoinMarketCap](https://coinmarketcap.com/api/), копит историю цен в базе данных и по расписанию обновляет её в фоне.

## Возможности

- Аутентификация по Bearer-токену (API-ключу): ключ из окружения и персональные ключи с регистрацией и сроком действия
- Управление списком отслеживаемых монет (CRUD)
- Получение актуальной цены из CoinMarketCap с сохранением в историю только при изменении цены
- История цен с фильтрами по времени, пагинацией и сортировкой
- Фоновая синхронизация цен: запись только при изменении цены
- Каталог всех криптовалют CoinMarketCap с поиском
- Корректная остановка фоновых задач и сервера по SIGINT/SIGTERM
- Документация OpenAPI 3.0 и Swagger UI
- Часовой пояс ответов и логов настраивается

## Требования

- **Для запуска в Docker:** Docker и Docker Compose v2 (команда `docker compose`).
- **Для локального запуска:** Node.js 26.1 или новее (см. `.nvmrc`) и npm.
- **Ключ CoinMarketCap.** Нужен бесплатный ключ: <https://coinmarketcap.com/api/>. Бесплатный тариф ограничен месячным числом кредитов, поэтому интервал фонового опроса по умолчанию 5 минут.

## Запуск

### 1. Подготовка (для любого варианта)

```bash
git clone <адрес репозитория>
cd crypto-tracker-api
cp .env.example .env
```

Открой `.env` и заполни две обязательные переменные:

- `CMC_API_KEY`: ключ CoinMarketCap;
- `BOOTSTRAP_API_KEY`: служебный токен для доступа к твоему API. Придумай длинную случайную строку, например:

  ```bash
  openssl rand -hex 32
  ```

Остальные переменные можно оставить как в примере (описание в разделе «Переменные окружения»).

### 2. Docker (рекомендуется)

```bash
docker compose up --build -d
```

Команда соберёт образ `crypto-tracker-api:prod` и запустит сервис `api` в фоне. Проверка:

```bash
docker compose ps                  # в колонке статуса должно появиться (healthy)
docker compose logs -f api         # логи сервиса
curl localhost:3000/health         # {"status":"ok"}
```

После запуска доступно:

| Адрес | Что это |
|---|---|
| <http://localhost:3000/docs> | Swagger UI |
| <http://localhost:3000/openapi.json> | спецификация OpenAPI |
| <http://localhost:3000/health> | проверка работоспособности |

Управление:

```bash
docker compose stop        # корректная остановка (SIGTERM, данные сохраняются)
docker compose start       # запуск остановленного сервиса
docker compose down        # удалить контейнер; база в томе остаётся
docker compose down -v     # удалить контейнер И том с базой (все данные пропадут)
```

**Данные.** База лежит в именованном томе Docker `app-data`, смонтированном в `/data`, поэтому данные переживают перезапуск и пересоздание контейнера. Переменные `PORT` и `DB_PATH` в Docker заданы в `docker-compose.yml` (`3000` и `/data/app.db`) и **перекрывают** значения из `.env`. Чтобы открыть сервис на другом порту хоста, измени строку `ports` (например, `"8080:3000"`).

### 3. Docker в режиме разработки

```bash
docker compose --profile dev up --build api-dev
```

Исходники монтируются в контейнер, а `tsx watch` перезапускает сервис при каждом изменении файла. База dev-режима лежит в отдельном томе `app-data-dev`, так что рабочие данные не затрагиваются. Нюансы:

- сервисы `api` и `api-dev` используют один и тот же порт 3000, поэтому одновременно запускай только один из них (`docker compose stop api`);
- каталог `node_modules` живёт в томе `dev-node-modules`, а не берётся с твоего компьютера. После изменения зависимостей пересобери образ (`docker compose --profile dev build api-dev`) и удали этот том (`docker compose --profile dev down`, затем `docker volume rm <имя тома из docker volume ls>`).

База создаётся в `./data/app.db` (путь задаётся `DB_PATH`). Сборка и запуск собранного кода:

### 5. Быстрая проверка сервиса

Ниже сквозной сценарий (подставь свой `BOOTSTRAP_API_KEY` или ключ из регистрации):

```bash
# 1. сервис жив
curl -s localhost:3000/health

# 2. регистрация: ключ вернётся один раз, сохрани его
curl -s -X POST localhost:3000/auth/register \
  -H 'Content-Type: application/json' -d '{"username":"alice"}'
export KEY=ctk_...          # значение apiKey.key из ответа

# 3. добавить монету (имя и id берутся из CoinMarketCap)
curl -s -X POST localhost:3000/coins -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' -d '{"symbol":"BTC"}'

# 4. получить актуальную цену (запись добавится, только если цена изменилась)
curl -s localhost:3000/coins/1/price -H "Authorization: Bearer $KEY"

# 5. посмотреть историю
curl -s localhost:3000/coins/1/history -H "Authorization: Bearer $KEY"

# 6. найти монету в каталоге
curl -s "localhost:3000/currencies?search=eth&limit=3" -H "Authorization: Bearer $KEY"
```

Вместо curl можно пользоваться Swagger UI на `/docs`: нажми **Authorize** и вставь ключ без слова `Bearer`.

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOOTSTRAP_API_KEY` | **обязательна** | Служебный токен для доступа к API. Принадлежит пользователю `system`, не истекает. Смена значения аннулирует прежний ключ при следующем запуске |
| `CMC_API_KEY` | **обязательна** | Ключ CoinMarketCap |
| `PORT` | `3000` | Порт HTTP-сервера (в Docker фиксирован в `docker-compose.yml`) |
| `DB_PATH` | `./data/app.db` | Путь к файлу SQLite (в Docker `/data/app.db`). БД в памяти (`:memory:`) запрещена |
| `CMC_BASE_URL` | `https://pro-api.coinmarketcap.com` | Адрес API CoinMarketCap |
| `HTTP_TIMEOUT_MS` | `5000` | Таймаут запросов к CoinMarketCap |
| `SYNC_INTERVAL_MS` | `300000` | Интервал фонового опроса цен, не меньше 60000 |
| `CURRENCY_SYNC_INTERVAL_HOURS` | `24` | Как часто обновлять каталог валют (1-168 часов) |
| `API_KEY_TTL_DAYS` | `90` | Срок жизни персональных ключей по умолчанию (1-365 дней) |
| `SHUTDOWN_TIMEOUT_MS` | `8000` | Сколько ждать корректной остановки, потом принудительный выход |
| `TIME_ZONE` | `UTC` | Часовой пояс времени в ответах и логах (имя IANA, например `Europe/Moscow`). В `.env.example` указано `Europe/Moscow` |

Приложение проверяет настройки при старте и падает с понятным сообщением, если что-то указано неверно.

## Аутентификация

Все эндпоинты, кроме `/health`, `/docs`, `/openapi.json` и `POST /auth/register`, требуют заголовок:

```
Authorization: Bearer <API-ключ>
```

Ключ бывает двух видов:

1. **Служебный** токен из `BOOTSTRAP_API_KEY`. Не истекает.
2. **Персональный**, выдаётся при регистрации и через `POST /auth/keys`. Формат `ctk_...`, показывается один раз, живёт `API_KEY_TTL_DAYS` дней (или столько, сколько указано в `expiresInDays`).

Ключи хранятся в базе только в виде хэша SHA-256. Ключи случайные и длинные (256 бит), поэтому медленные алгоритмы хэширования паролей не нужны.

Неверный, неизвестный, просроченный или отсутствующий ключ всегда даёт одинаковый ответ 401 (причина видна только в логах сервера). Ключ нужно продлевать **до** истечения: просроченным ключом новый выпустить нельзя.

## Описание API

Интерактивная версия с возможностью выполнять запросы: Swagger UI на `/docs`. Машиночитаемая спецификация: `/openapi.json`.

### Общие правила

- Тела запросов и ответов в формате JSON. Для запросов с телом нужен заголовок `Content-Type: application/json`.
- Каждый ответ содержит заголовок `X-Request-Id` (тот же идентификатор есть во всех записях лога этого запроса).
- Время в ответах имеет формат ISO 8601 с явным смещением (см. раздел «Время и часовой пояс»).
- Идентификатор монеты `id` в путях это идентификатор внутри этого сервиса, а не id CoinMarketCap (он отдаётся отдельным полем `cmcId`).
- Неизвестные поля в теле запроса и неизвестные параметры в query-строке отвергаются с кодом 400.
- Формат ошибок описан в разделе «Формат ошибок».

### Здоровье

#### `GET /health`

Не требует авторизации. Используется Docker healthcheck.

```json
{ "status": "ok" }
```

### Регистрация и ключи

#### `POST /auth/register`

Создаёт пользователя и первый ключ. Не требует авторизации.

Тело запроса:

| Поле | Тип | Правила |
|---|---|---|
| `username` | строка | 3-32 символа: латинские буквы, цифры, `_`. Регистр не важен, хранится в нижнем регистре. Имя `system` занято |

Ответ `201 Created` (заголовок `Cache-Control: no-store`):

```json
{
  "user": { "id": 2, "username": "alice", "createdAt": "2026-10-07T13:00:00.000+03:00" },
  "apiKey": {
    "id": 2,
    "name": "default",
    "prefix": "ctk_1a2b3c4d",
    "createdAt": "2026-10-07T13:00:00.000+03:00",
    "expiresAt": "2027-01-05T13:00:00.000+03:00",
    "expired": false,
    "key": "ctk_1a2b3c4d5e6f..."
  }
}
```

Поле `key` это полный ключ. **Он показывается только в этом ответе**, в базе хранится лишь хэш.

Ошибки: `400` (некорректное имя, лишние поля), `409` (имя занято).

#### `GET /auth/keys`

Список ключей текущего пользователя, от старых к новым. Сами ключи не возвращаются, только метаданные.

```json
[
  {
    "id": 2,
    "name": "default",
    "prefix": "ctk_1a2b3c4d",
    "createdAt": "2026-10-07T13:00:00.000+03:00",
    "expiresAt": "2027-01-05T13:00:00.000+03:00",
    "expired": false
  }
]
```

`expiresAt` равен `null` только у служебного ключа (`prefix: "env"`). Ошибки: `401`.

#### `POST /auth/keys`

Выпускает новый ключ для текущего пользователя. Тело необязательно.

| Поле | Тип | Правила |
|---|---|---|
| `name` | строка | 1-50 символов, по умолчанию `api-key` |
| `expiresInDays` | целое число | 1-365, по умолчанию `API_KEY_TTL_DAYS` |

```bash
curl -s -X POST localhost:3000/auth/keys -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' -d '{"name":"ci","expiresInDays":30}'
```

Ответ `201 Created`: объект ключа как в списке плюс поле `key` с полным значением (заголовок `Cache-Control: no-store`). Ошибки: `400`, `401`.

#### `DELETE /auth/keys/{id}`

Отзывает ключ с указанным id. Можно отзывать только свои ключи.

Ответ `204 No Content`. Ошибки: `400` (некорректный id), `401`, `404` (ключа нет или он чужой), `409` (нельзя отозвать последний действующий ключ; просроченные ключи отзывать можно всегда).

### Монеты

Объект монеты:

```json
{
  "id": 1,
  "cmcId": 1,
  "symbol": "BTC",
  "name": "Bitcoin",
  "createdAt": "2026-10-07T13:00:00.000+03:00",
  "updatedAt": "2026-10-07T13:00:00.000+03:00"
}
```

Список монет общий для всех пользователей.

#### `POST /coins`

Начинает отслеживать монету. Сервис ищет тикер в CoinMarketCap, поэтому имя и `cmcId` берутся оттуда.

| Поле | Тип | Правила |
|---|---|---|
| `symbol` | строка | тикер CoinMarketCap: 1-20 латинских букв или цифр. Регистр не важен, хранится в верхнем |

Ответ `201 Created` с заголовком `Location: /coins/{id}` и объектом монеты. Если у нескольких монет один тикер, выбирается та, что выше в рейтинге CoinMarketCap.

Ошибки: `400`, `401`, `404` (тикер неизвестен CoinMarketCap), `409` (монета уже отслеживается), `502`/`504` (CoinMarketCap недоступен или не ответил вовремя).

#### `GET /coins`

Все отслеживаемые монеты, от старых к новым. Ответ `200`: массив объектов монет (пустой массив, если монет нет). Ошибки: `401`.

#### `GET /coins/{id}`

Ответ `200`: объект монеты. Ошибки: `400` (id не положительное целое), `401`, `404`.

#### `PATCH /coins/{id}`

Меняет отображаемое имя. Тикер и `cmcId` менять нельзя: они определяют, чьи цены лежат в истории.

| Поле | Тип | Правила |
|---|---|---|
| `name` | строка | 1-100 символов |

Ответ `200`: обновлённый объект монеты (`updatedAt` изменится). Ошибки: `400`, `401`, `404`.

#### `DELETE /coins/{id}`

Удаляет монету **вместе с её историей цен**. Ответ `204 No Content`. Ошибки: `400`, `401`, `404`.

### Цены

#### `GET /coins/{id}/price`

Запрашивает актуальную цену в CoinMarketCap и возвращает её. В историю цена записывается, **только если она отличается от последней сохранённой**.

```json
{
  "coinId": 1,
  "symbol": "BTC",
  "currency": "USD",
  "price": 43250.5,
  "fetchedAt": "2026-10-07T13:00:00.000+03:00",
  "recorded": true
}
```

Поля ответа:

- `fetchedAt`: момент, когда цена была запрошена у провайдера (если запись добавилась, он совпадает со временем записи в истории);
- `recorded`: `true`, если в историю добавлена новая запись, и `false`, если цена равна последней сохранённой и запись не создавалась.

Сравнение идёт с последней записью монеты в базе, в том числе сделанной фоновой задачей. Каждый вызов обращается к CoinMarketCap и тратит кредиты, даже если запись не добавилась. Если провайдер не вернул цену для монеты, в историю ничего не пишется.

Ошибки: `400`, `401`, `404`, `502`/`504` (провайдер недоступен, отклонил запрос или не ответил вовремя).

#### `GET /coins/{id}/history`

История цен монеты из базы данных (к CoinMarketCap не обращается).

| Параметр | По умолчанию | Правила |
|---|---|---|
| `from` | нет | начало диапазона, включительно. ISO 8601 **с часовым поясом**: `2026-10-07T10:00:00Z` или `2026-10-07T13:00:00+03:00`. Годы 1970-2200. Знак `+` в URL кодируется как `%2B` |
| `to` | нет | конец диапазона, включительно, тот же формат. Не раньше `from` |
| `limit` | `100` | размер страницы, 1-1000 |
| `offset` | `0` | сколько записей пропустить, 0-1 000 000 |
| `order` | `desc` | `desc` (новые первыми) или `asc` |

```bash
curl -s "localhost:3000/coins/1/history?from=2026-10-07T00:00:00Z&limit=50&order=asc" \
  -H "Authorization: Bearer $KEY"
```

Ответ `200`:

```json
{
  "coinId": 1,
  "symbol": "BTC",
  "currency": "USD",
  "items": [
    { "price": 43310.12, "fetchedAt": "2026-10-07T13:10:00.000+03:00" },
    { "price": 43250.5, "fetchedAt": "2026-10-07T13:00:00.000+03:00" }
  ],
  "total": 2,
  "limit": 100,
  "offset": 0
}
```

`total` это число записей, подходящих под фильтр, без учёта `limit` и `offset`. Для монеты без истории вернётся пустой список (`items: []`, `total: 0`). Цена записывается только при изменении (и фоновой задачей, и `GET /coins/{id}/price`), поэтому промежуток без записей означает, что цена не менялась.

Ошибки: `400` (некорректные параметры, неизвестные или повторяющиеся параметры, `from` позже `to`), `401`, `404` (монеты нет).

### Каталог валют

#### `GET /currencies`

Каталог криптовалют CoinMarketCap из локальной базы (к провайдеру не обращается). Обновляется в фоне раз в сутки. Подойдёт, чтобы найти тикер для `POST /coins`.

| Параметр | По умолчанию | Правила |
|---|---|---|
| `search` | нет | подстрока тикера или названия, 1-50 символов, без учёта регистра (только для латинских букв) |
| `limit` | `100` | размер страницы, 1-500 |
| `offset` | `0` | сколько записей пропустить, 0-1 000 000 |

Ответ `200`, лучшие по рейтингу первыми (монеты без рейтинга в конце):

```json
{
  "items": [
    { "cmcId": 1, "symbol": "BTC", "name": "Bitcoin", "slug": "bitcoin", "rank": 1 },
    { "cmcId": 1027, "symbol": "ETH", "name": "Ethereum", "slug": "ethereum", "rank": 2 }
  ],
  "total": 10432,
  "limit": 100,
  "offset": 0,
  "syncedAt": "2026-10-07T04:00:00.000+03:00"
}
```

До первого успешного обновления каталог пуст (`items: []`, `syncedAt: null`). Ошибки: `400`, `401`.

## Формат ошибок

Все ошибки имеют одну форму:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Validation failed",
    "details": [{ "field": "symbol", "message": "must be 1-20 latin letters or digits" }]
  }
}
```

Поле `details` присутствует только у ошибок валидации.

| Статус | Код | Когда |
|---|---|---|
| 400 | `VALIDATION_ERROR` | неверное тело, параметр пути или запроса, битый JSON |
| 401 | `UNAUTHORIZED` | ключ отсутствует, неверен или просрочен (заголовок `WWW-Authenticate: Bearer`) |
| 404 | `NOT_FOUND` | нет такого ресурса или маршрута, тикер неизвестен CoinMarketCap |
| 409 | `CONFLICT` | дубликат (монета, имя пользователя), отзыв последнего ключа |
| 502 | `EXTERNAL_API_ERROR` | CoinMarketCap недоступен, отклонил запрос или вернул мусор |
| 504 | `EXTERNAL_API_ERROR` | CoinMarketCap не ответил вовремя |
| 500 | `INTERNAL_ERROR` | непредвиденная ошибка (детали только в логах, найти запись можно по `X-Request-Id`) |

## Время и часовой пояс

В базе время всегда хранится в UTC. В ответах API и в логах оно показывается в часовом поясе `TIME_ZONE` с явным смещением, например `2026-10-07T13:00:00.000+03:00` (при `UTC` используется суффикс `Z`). Это один и тот же момент времени, меняется только представление. Фильтры `from` и `to` принимают любое смещение.

## Фоновые задачи

### Синхронизация цен

Каждые `SYNC_INTERVAL_MS` задача одним запросом получает цены всех отслеживаемых монет и записывает их **только если цена изменилась** по сравнению с последней записью монеты в базе. Поэтому:

- отсутствие записи за период означает, что цена не менялась;
- возврат к прежней цене после изменения сохраняется (сравнение идёт с последней записью);
- пакет записывается одной транзакцией;
- первый опрос выполняется сразу после запуска;
- ошибка итерации (недоступный CoinMarketCap, лимиты) логируется, задача продолжает работу;
- запуски не накладываются друг на друга даже при медленных ответах.

Тем же правилом пользуется `GET /coins/{id}/price`: цена возвращается всегда, а запись в историю добавляется, только если цена отличается от последней сохранённой. Записи ручных вызовов и фоновой задачи сравниваются между собой.

### Каталог валют

Раз в `CURRENCY_SYNC_INTERVAL_HOURS` часов задача загружает список активных криптовалют CoinMarketCap в таблицу `currencies` (порядка десятков тысяч строк, для SQLite это пустяк). Обновление идёт одной транзакцией, пустой ответ провайдера не затирает каталог, а при перезапуске свежий каталог не загружается повторно, чтобы не тратить кредиты.

### Остановка

По SIGINT/SIGTERM сервис перестаёт принимать запросы, дожидается активных запросов и текущих итераций фоновых задач, закрывает базу и завершается с кодом 0. Если остановка не уложилась в `SHUTDOWN_TIMEOUT_MS`, процесс завершается принудительно с кодом 1. В Docker процесс запускается напрямую под `tini` (`node dist/Server.js`), а не через `npm start`, иначе сигнал не дойдёт до приложения.

## Архитектурные решения

**`node:sqlite` вместо внешнего драйвера.** Условия задания (Node.js 18+ и «только указанные библиотеки и стандартные возможности Node.js») несовместимы с SQLite без сторонних пакетов: во встроенном виде он появился только в новых версиях Node. Выбран встроенный модуль (в Node 26 он отмечен как release candidate) и минимальная версия поднята до 26.1: в более ранних версиях встречается ошибка обрезки текста в `node:sqlite`. Драйвер спрятан за слоем репозиториев (`src/db/connection.ts` и `src/repository/`), так что при необходимости его можно заменить, например на `better-sqlite3`, поменяв несколько файлов.

**Без ORM, только SQL.** Все запросы параметризованы (`?`). В SQL подставляются только константы из кода, а направление сортировки выбирается из фиксированной таблицы.

**Данные не хранятся в памяти приложения.** Монеты, цены, ключи, каталог валют и даже время последней синхронизации лежат в БД. В памяти остаются лишь таймеры и флаги фоновых задач. База всегда файловая, `DB_PATH=:memory:` отвергается при старте, файл БД не хранится в репозитории (`data/` в `.gitignore`, в Docker том).

**Внешние запросы.** У клиента CoinMarketCap есть таймаут, ограничение размера ответа, запрет перенаправлений и разбор всех статусов. Таймаут превращается в 504, остальные сбои в 502 с общим текстом, подробности только в лог. Объект ошибки axios нигде не логируется и не пробрасывается, потому что в нём лежат заголовки с ключом провайдера.

**Валидация без библиотек.** Каждая функция валидации принимает `unknown`, собирает все найденные проблемы и возвращает очищенные данные. Неизвестные поля тела и параметры запроса отвергаются.

**Время.** Хранение в UTC, представление в настраиваемом часовом поясе средствами встроенного `Intl`, без внешних библиотек.

**Dev-инструменты.** `typescript`, `tsx`, `ts-jest` и пакеты `@types/*` нужны только для разработки и сборки и не попадают в рабочий образ. Это стандартные средства для TypeScript и тестов на Jest.

**Документация.** Спецификация лежит в JSON-файле: так не нужна отдельная библиотека для разбора YAML. Тесты проверяют структуру спецификации и соответствие ей реальных ответов, поэтому документация не устаревает незаметно.

## Ограничения и допущения

- **Регистрация открыта.** Любой может получить ключ. Защиты от массовой регистрации (лимитов запросов) нет.
- **Паролей нет, ключ и есть учётная запись.** Если срок единственного действующего ключа истёк, войти нельзя. Новый ключ нужно выпускать до истечения старого. Последний действующий ключ отозвать нельзя, чтобы не заблокировать себя.
- **Список монет общий** для всех пользователей. Авторизация определяет, кто делает запрос, но не разделяет данные.
- **Квота CoinMarketCap.** Каждый вызов `GET /coins/{id}/price` обращается к провайдеру и тратит кредиты. Фоновые задачи тоже тратят их, поэтому интервалы по умолчанию умеренные.
- **История хранит изменения.** Фоновая задача и `GET /coins/{id}/price` пишут цену только при её изменении, поэтому «цена на момент T» это последняя запись не позже T. Ответ `GET /coins/{id}/price` с `recorded: false` подтверждает, что цена на момент запроса равна последней записи.
- **Только USD.** Цены запрашиваются в долларах США.
- **Миграции простые.** Схема создаётся идемпотентно (`CREATE TABLE IF NOT EXISTS`) в одной транзакции. Для задания достаточно, для развития проекта понадобится версионирование схемы.
- **Просроченные ключи не удаляются автоматически.** Они просто перестают работать и их можно отозвать вручную.
- **Поиск в каталоге** без учёта регистра только для латинских букв.
